# Agent field guide

Durable notes for anyone — human or agent — starting work in this repository.
Append what you learn; keep it to things that are true and not obvious from the
code. `AGENTS.md` states the rules you must follow; this file records what costs
time to rediscover.

## What this is

Langbank is a registry of static facts about programming languages, ecosystems,
registries, tools and toolchains — 827 language files and 1,111 toolchain files
under `data/`, compiled into `&'static` tables at build time. It walks no
filesystem, spawns no process and parses no source; it describes, and consumers
run.

It is the fleet's leaf: entl, treebank and propbank depend on it, and it depends
on none of them. Grep for `entl` and every hit is prose — there is no path
dependency on a sibling checkout anywhere, and nothing here needs one.

Four crates, one repository: the root `langbank` library, plus workspace members
`detect/` (runs the content rules langbank only describes), `sync/` (the CLI that
checks `data/` against upstreams), and `web/` (langbank.dev, axum + maud).

## Building and testing

`rust-toolchain.toml` pins **1.97.1** — deliberately matching entl, infact and
cowbird. Nothing else is needed: no system packages, no Node, no submodules.

```sh
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

`Cargo.lock` is committed — a recent decision (`build: commit the lockfile the
workspace ships binaries from`), because this workspace ships binaries
(`langbank-web`, `langbank-sync`) where a reproducible resolve matters. Keep it
in the commit.

Beyond the three commands, CI runs three gates that are worth knowing about
before they surprise you:

- **`straitjacket`**, pinned to `v0.1.1` on purpose. The action installs
  `latest` by default, and a withdrawn rule turns a checked-in config into a
  hard error — which is how this step first went red. Its two exemptions and
  their reasoning are in `straitjacket.toml`.
- **"The leaf stays a leaf."** `cargo metadata` is read and the `langbank`
  package's runtime dependencies must be a subset of
  `inventory serde serde_json toml`. One convenient `cargo add` in the root
  directory fails the build, which is the point.
- **"Workflows only call scripts that exist."** It greps the workflows for
  `tools/*.py` and `tools/*.rb` names and fails when one is missing, because
  `drift.yml` runs only on `main` and on a schedule — a workflow calling a
  deleted script stays green through review and turns `main` red afterwards.
  That is not hypothetical; it happened when `sync-heuristics.py` was ported.

`fleet-lint.yml` is distributed by conf; edit it there. Its `hawk` job pins Rust
1.98.0 rather than the repository toolchain, runs only when Rust changed, and is
advisory.

## The build script is the whole story

`build.rs` is the largest file in the repository (~1,000 lines) and reads every
`data/**/*.toml`, string-building a Rust source file that `src/lib.rs` pulls in
with `include!(concat!(env!("OUT_DIR"), "/registries.rs"))`. `src/lib.rs` itself
is a ~90-line hub. So:

- **Never edit generated output, and never add a fact by writing Rust.** `data/`
  is the source of truth.
- **A build script that cannot read its data panics on purpose.** The crate-wide
  `clippy::panic`/`expect_used` denials are lifted for that file alone. An empty
  registry that compiles is worse than a build failure, because a consumer sees
  a language-free world and no error.
- Ids that collide with Rust keywords or start with a digit are special-cased in
  the generator (`Move`, `Self`, `4d`), so a new language file with an awkward id
  may need a case there rather than a rename.
- `cargo:rerun-if-changed` covers `data` as a directory plus each file, so
  editing `data/` does rebuild — but a rename that leaves the directory
  untouched will not.

## Landmines

**A hard-coded count.** `tests/generated_data.rs` asserts
`language_profiles().len() == 827`, one profile per file in `data/languages`.
Adding or removing a language file breaks that test until the literal is
updated. Separately, `data/sources/linguist.toml` pins upstream's count (826), a
revision and a sha256 — those are checked by `langbank-sync linguist check`, not
by `cargo test`, so they can be out of step with each other for a while.

**`data/heuristics.toml` is generated, and it is 61 KB.** Its header says so:

```
# @generated by `cargo run -p langbank-sync -- heuristics create` from
# github-linguist/linguist (MIT).
```

Do not hand-edit it. `straitjacket.toml` excludes it from the file-size rule for
exactly this reason. `heuristics check` in `drift.yml` verifies it against
upstream.

**Registration happens at link time, so a library that compiles proves nothing.**
`inventory` collects registrations when the binary links; the facts have to be
tested from `tests/`, which links the whole crate. A unit test inside `src/` is
not a substitute.

**README and AGENTS.md still name Python tools that no longer exist.** Grep for
`tools/verify-toolchains.py`, `tools/coverage-report.py`, `tools/sync-linguist.py`
and `tools/sync-purl.py` (the last also in `data/sources/purl.toml`'s header).
All of them were ported into the `langbank-sync` crate as subcommands, and
`tools/` now holds one file: `extract-dependabot.rb`. The CI guard only checks
what *workflows* call, so stale prose survives it. The live commands are:

```sh
cargo run -p langbank-sync                      # prints the source list
cargo run -p langbank-sync -- linguist check    # and corpora, comments, lspconfig,
                                                # mason, static-analysis, dependabot,
                                                # contested, purl, heuristics
cargo run -p langbank-sync -- coverage
cargo run -p langbank-sync -- toolchains --strict
```

Every source takes `check` (report what is missing, non-zero when something is)
or `create` (write what is missing, never overwriting what exists). `dependabot`
is the odd one: it consumes JSON that `ruby tools/extract-dependabot.rb` emits
from a clone of dependabot-core, which is why `drift.yml` clones it.

**`drift.yml` is the daily reality check** (cron `17 6 * * *`, plus every push to
main). It runs every `check` and the toolchain prober. A failure there is
usually upstream moving, not this repository breaking.

## Where the surprising code lives

`detect/src/lib.rs` holds the hand-written content-rule engine, and two of its
decisions are load-bearing and easy to undo by accident:

- Patterns are compiled with `.multi_line(true)`, because linguist's rules are
  Ruby-derived and assume `^`/`$` match at every line boundary. Rust's regex
  crate does not do that by default, and the anchoring bug that follows from
  forgetting it has already shipped once.
- The compiled-regex cache leaks its regexes to get `'static` and locks with
  `lock_recovering`, which deliberately *recovers* from mutex poisoning rather
  than propagating it. A single panic anywhere used to switch every content rule
  off, silently and permanently, for the life of the process.

`sync/src/sources/heuristics.rs` decides which upstream patterns are portable by
actually calling `regex::Regex::new` on them rather than guessing — which caught
cases the earlier Python guesser missed, such as an unescaped `{` that Ruby
reads as a literal and Rust rejects as a malformed quantifier.

`web/src/lib.rs` keeps every page as a pure function with no I/O, so pages can be
rendered in tests without binding a port; `main.rs` holds the routes. Its
`port_from` treats a set-but-unparsable `PORT` as a hard error rather than
falling back to 8080, so a misconfigured Fly deploy fails loudly instead of
timing out its health check with nothing in the logs.

## Deployment

langbank.dev runs on Fly from `web/`. `fly.toml` is production (app `langbank`,
always-on); `fly.preview.toml` is the per-PR app (idles to zero). The `Dockerfile`
is `cargo-chef`-based and builds only `-p langbank-web` into a
`debian:bookworm-slim` image. `/health` reports registry counts rather than a
bare `ok`, and the deploy smoke test asserts those counts are non-zero — a
deploy that boots with an empty registry is the failure that check exists for.
`docs/deploy.md` and `docs/fly-setup.sh` have the rest.

## Also in docs/

`docs/sources.md` records which upstreams are checked against and, importantly,
which are *refused* on licence grounds (helix MPL-2.0, cloc GPL-2.0, renovate and
libraries.io AGPL-3.0). Check it before absorbing a new source.
`docs/verbosity.md` explains a removed feature and names the commit to recover it
from — the numbers were deleted because their generator was lost and they could
not be reproduced.
