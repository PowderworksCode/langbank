# Verbosity, and why langbank no longer carries it

langbank used to ship 142 measurements of relative source verbosity, taken from
the Exercism corpus, reachable as `verbosity(id)` and `verbosity_ratio(a, b)`.
They were removed in the commit that added this file.

They are removed rather than migrated for a reason worth stating: **they could
not be reproduced.** The header said `@generated by tools/verbosity`, and that
tool was already gone. It pointed at `docs/verbosity-exercism.md` and
`notes/verbosity.md` for the method, and neither existed. A generated table
whose generator and method write-up have both been lost is a number nobody can
check, which is the opposite of what the rest of this repository is for.

The measurements are in git. To read them:

    git show c79303dc736c8d74cb78944e3d99f8fba580594d:src/verbosity.rs

## What the measurements were, in the words of the file itself

Relative source verbosity of the profiled languages.

Every number here is a statistic derived from the Exercism corpus: how much
program text each language needs for exercises that two languages both
implement, with comments and blank lines removed. That corpus is licensed
under the MIT License. Entl does not redistribute it; only these measurements.

Entl reports the measurement, not a verdict. Verbosity here is source size on small self-contained pieces, which rewards languages with terse standard libraries and charges languages that require declarations, imports, or a class to hold `main`. It does not extrapolate to large programs: measured on a mid-sized one instead, the same languages spread roughly twice as far apart. It is not a claim
about readability.

It is also not a porting factor. This measures what a language needs when
someone writes a solution from the specification. Translating an existing
program into another language is a different quantity and can run the other
way: Bun's Zig-to-Rust rewrite expanded by about 1.37x in tokens, while
independently written Rust and Zig solutions put Rust at roughly 0.7x Zig.

See `docs/verbosity-exercism.md` for the method, the full matrix, and how far a
single index per language falls short of explaining the pairs it came from.

## If this comes back

It should come back as `data/`, generated by a tool that lives in this
repository, against a corpus revision recorded in the data — the same shape as
every other registry here. A pair matrix is an awkward fit for one-file-per-entry
and would need its own arrangement, which is part of why it was never migrated.
